## 一、引言与个人角色

本项目要解决的问题是：在课程给定的 30,000 条信用卡客户历史记录上，预测客户下月是否违约，
并做成一个能在本地运行、可交互查看分析结果的可视化界面。团队整体完成数据处理、模型训练、
测试优化、界面设计、文案汇报五个环节。

我在团队中承担**界面设计**这一棒，分工边界是：把前两棒产出的数据与模型成果，变成一个
满足课程验收要求、可直接运行和交互的界面程序。具体包括四个页面的实现、图表与统计卡片的
呈现、阈值的交互探索、以及最终评价页对锁定模型结果的加载展示。我不负责数据清洗和模型训练，
也不改动模型的指标口径。

## 二、个人具体工作

### （一）工作项一：数据加载与「数据概览」页实现

- **输入**：课程数据文件 `data/01_credit_default.csv`（30,000 条，含 `split` 划分列与
  `default_next_month` 标签）；题目要求「数据核查：按 split 展示三组样本量、违约率、缺失值和
  record_id 重复数，并绘制授信额度、年龄及还款状态分布」。
- **动作**：用 `pandas` 读取 CSV（`encoding="utf-8-sig"`，保证 Excel 中文不乱码），用
  `@st.cache_data` 做缓存避免每次交互都重读 3MB 数据；把统计量算成 5 个 `st.metric` 卡片；
  用 Plotly 画两张叠加直方图（按「违约/正常」着色）；还款状态分布做成**可切换月份**的
  柱状图，并用一个中文映射函数把 `-2 / -1 / 0 / 1~8` 编码翻译成「无消费 / 全额还款 /
  循环信用 / 逾期 N 个月」。
- **输出**：`app.py` 中的 `page_overview()` 函数与 `load_data()`、`pay_status_cn()`。
  验收要点：负值还款状态按**编码**解释，而不是当缺失值处理。

### （二）工作项二：「模型比较」页与验证集阈值选择

- **输入**：题目要求「实现全判不违约基线、逻辑回归和至少一种树模型；预处理仅在训练集拟合；
  用验证集比较模型，选择一个报警阈值，并显示选择依据」。
- **动作**：在 `train_models()` 中只取 `split == "train"` 的行拟合模型——
  `RandomForestClassifier(n_estimators=300, random_state=42)` 和
  `make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))`（标准化**放在 Pipeline 里**，
  只在训练集 fit，再应用到验证集，符合课程口径）；用 `pick_threshold()` 在验证集上按
  「召回率 ≥ 70% 的候选中精确率最高」自动选阈值；页面提供模型单选和阈值滑块，滑块改变
  即时更新精确率、召回率、报警人数、其中真正违约四个指标，并画一条阈值-指标曲线标出自动阈值。
- **输出**：`page_compare()`、`train_models()`、`pick_threshold()`、`pr_curve_points()`。

### （三）工作项三：「最终评价」页对接组员交付的锁定结果

- **输入**：测试优化组员交付的 `models/rf_best_model.pkl`（146MB）、`models/test_metrics.json`、
  `models/test_predictions.csv`。
- **动作**：关键设计决策是**这页不做任何计算**——直接加载组员锁定的 json / csv 展示，
  以保证「测试集只评价一次」不被反复调参破坏。用 `confusion_matrix()` 从逐条预测还原混淆矩阵，
  用 `roc_curve()` 画 ROC 曲线，并把漏判（FN）和误判（FP）单独做成两张卡片，说明业务含义。
- **输出**：`page_final()`、`load_locked_metrics()`、`load_locked_model()`、`load_test_predictions()`。

### （四）工作项四：「客户风险演示」页

- **输入**：题目要求「输入或选择一条已有客户记录，展示风险概率、所选阈值、风险提示和主要
  输入信息；若选择测试记录，须将事后真实标签与预测结果分开标示」。
- **动作**：用 `st.session_state` 保存当前客户编号，支持「按编号查询」和「随机抽一位」两种交互；
  把该客户的六个月还款状态、账单金额、还款金额整理成表格展示；用锁定模型算违约概率，
  与验证集选定的阈值比较后给出高风险/低风险结论。特别处理：**只有测试集记录**才显示事后
  真实标签，并放在一个独立的边框块里注明「预测时模型不可见」，训练集/验证集的记录则明确
  提示「模型拟合阶段见过其标签，故不展示对照」，避免误导。
- **输出**：`page_demo()`。

### （五）工作项五：多页面导航重构与自查

- **输入**：本人对四个页面做的实际运行测试（含跨页切换测试）。
- **动作**：初版用单文件内的 `st.sidebar.radio` 切换页面，实测发现切换后上一页最后两个
  统计卡片残留可见。改用 `st.navigation` + `st.Page` 多页面模式重构（每次切换渲染全新容器），
  消除残留；并给「演示页/最终评价页」补上模型或指标文件缺失时的明确错误提示。
- **输出**：`app.py` 入口部分的重构、各页的 `try / except FileNotFoundError` 分支。

## 三、使用的关键技术

| 技术 / 工具 | 类别 | 在本任务中的作用 | 选择理由 |
| --- | --- | --- | --- |
| Streamlit | 界面框架 | 四个可切换页面、统计卡片、滑块与选择控件 | 纯 Python 即可生成可交互界面，适合本地运行的教学演示，改一行代码即时刷新 |
| pandas | 数据处理 | 读取 CSV、按 split 分组统计、整理图表数据 | 单机处理 3 万行绰绰有余，分组聚合与表格构造最直接 |
| scikit-learn | 机器学习 | 随机森林与逻辑回归训练、ROC-AUC / 精确率 / 召回率 / 混淆矩阵计算 | 与组员模型训练的库一致，保证界面重训结果可与交付模型对照 |
| Plotly | 可视化 | 直方图、柱状图、阈值曲线、混淆矩阵热力图、ROC 曲线 | 支持悬停与缩放，且能方便地统一设置中文轴名与图例（课程要求图表标明指标名称） |

整体上，这套技术组合的匹配点是：数据规模只有 3 万行、任务是教学性质的单机运行，
因此不需要分布式框架或深度学习，重点是**可解释、可复现、能现场演示**。
界面层用 Streamlit 把 scikit-learn 的计算结果直接呈现，这样每个数字都能追到代码。

### （二）关键步骤说明

1. **数据预检与缓存**：启动时先尝试读取 CSV，成功则在侧边栏给出「数据已加载」的成功提示，
   失败则明确报出缺少的文件名并停止，避免页面白屏或崩溃。
2. **训练集重训**：只在 `split == "train"` 上拟合逻辑回归与随机森林，用 `@st.cache_resource`
   缓存，避免每次拖动滑块都重新训练 300 棵树。
3. **阈值选择与展示**：验证集上用 `pick_threshold` 选阈值，页面上把「自动阈值」画成红虚线、
   「当前滑块」画成绿点线，让选择依据可被直接看见。
4. **锁定结果的加载展示**：最终评价页与演示页只读组员交付的文件，界面不重算指标，
   确保测试集只被评价一次。

## 五、遇到的问题与解决

### （一）问题一：切换页面后出现上一页的残留元素

- **现象**：用单文件内 `st.sidebar.radio` 切换页面时，切到「客户风险演示」页后，
  上一页最后两个统计卡片（「record_id 重复数」「缺失值总数」）仍然显示在页面底部。
- **排查思路**：先怀疑是渲染延迟，等待后仍在；再怀疑是自己写的页面函数顺序有问题，
  检查后发现各页面函数内部没有跨页变量。最后判断是 Streamlit 在同一容器里复用元素，
  页面函数切换时旧的 `st.metric` 没有被清理。
- **最终解法**：把单文件 radio 切换改为 `st.navigation` + `st.Page` 多页面模式，
  每次切换由框架渲染全新容器。重构后在浏览器里逐页点了一遍，四个页面都不再有残留。

### （二）问题二：界面内重训的指标和组员交付的指标对不上

- **现象**：界面内重训的随机森林，验证集 AUC 是 0.7787；而组员交付的锁定模型在测试集上
  AUC 是 0.7587。一开始怀疑是自己特征列用错或数据口径不一致，不敢把「最终评价」页
  接上组员的文件。
- **排查思路**：先核对 `FEATURES` 与该模型 `feature_names_in_` 是否完全一致（确认 23 列一致）；
  再核对训练/验证/测试的划分是否为同一份 CSV 的 `split` 列（确认一致）；
  最后注意到两者不是同一集合（一个是验证集、一个是测试集），且 scikit-learn 版本不同
  （本机 1.9.1，组员环境更早）。用同一集合比对后差异小于 0.001，属于版本差异量级。
- **最终解法**：确认口径一致后，采纳「**比较页做界面内交互探索（验证集口径），
  最终评价页和演示页直接读组员锁定的文件**」的分工，既保证可交互，又保住测试集只评一次。

### （三）问题三：窄窗口下统计卡片数值被省略号截断

- **现象**：在较窄的浏览器窗口里，概览页与最终评价页的统计卡片数值显示成省略号，
  例如「总样本数」显示为 `30,...`、「ROC-AUC」显示为 `0.7...`，
  导致系统截图上的数值看不全，不好作为提交材料。
- **排查思路**：先把鼠标悬停到卡片上，能看到完整数值，说明是显示问题而不是算错；
  再用不同窗口宽度反复打开同一页，发现窗口越窄截断越明显，判断根因是
  **5 列布局下每列宽度不足以容纳 `st.metric` 的大字号数值**，而长字符串
  （如「20,999 / 4,500 / 4,501」）在窄列下更容易被截断。
- **最终解法**：把 5 列改为 **3+2 两行布局**，并精简过长的数值与标签——
  授信额度由「50,000 元」改为「5.0 万新台币」，三集样本量从卡片移入页面说明文字
  与已有表格。改完重新实测四个页面，并重拍系统截图。

## 八、AI 生成代码的阅读理解与心得

### （一）心得一：阈值选择函数 `pick_threshold` 的向量化实现

- **代码作用**：输入验证集的真实标签和预测概率，输出一个报警阈值，以及该阈值下的精确率和
  召回率。选择规则是：在所有满足「召回率 ≥ 70%」的候选阈值里，取精确率最高的那个。
- **我的阅读过程**：先看明白 `np.argsort(-proba)` 是把客户按风险概率从高到低排序；
  然后用 `np.cumsum` 对排序后的标签做累积求和——`tp` 就是前 k 名里的真正违约数，
  `fp` 就是前 k 名里的误报数，于是「前 k 名报警」这一族阈值（共 n 个候选）的精确率、
  召回率可以一次性算完，而不是写两层循环。为了确认自己读懂了，我用小样本手工验算过一遍，
  并打印了中间变量对照。
- **调整与心得**：AI 写得合理且高效（O(n log n) 而非 O(n²)），但有两点我自己补上了：
  ① 当召回率约束一个候选都不满足时的兜底返回（AI 初版会直接报错）；
  ② 用 `np.errstate` 屏蔽除以 0 的警告。心得是：AI 给的向量化写法值得学，
  但**边界情况它常常不管**，必须自己补。

### （二）心得二：多页面导航的重构

- **代码作用**：把原来单文件内 `st.sidebar.radio` 的手写切换，改成
  `st.navigation([st.Page(...), ...])` 再由 `page.run()` 执行，从而让每次页面切换都是独立渲染。
- **我的阅读过程**：先查 Streamlit 官方文档确认 `st.Page` 的参数（标题、图标、默认页）；
  再对照重构前后的代码差异，确认每个页面函数都从「被 if 分支调用」变成「被注册为页面对象」；
  最后用浏览器逐页点击验证残留是否消失。
- **调整与心得**：AI 的方案确实对症，但**是我先观察到残留现象并描述清楚，它才给出这个方案**——
  这说明要有效使用 AI，关键是我自己能把「现象」描述准（哪两个卡片、在哪个页面、什么时候出现）。
  另外重构后原文件里围绕 radio 的 `if/else` 长分支需要一起清理，这部分是我手动整理的。

## 九、总结

我在本项目中的独立交付是 `app.py`（四个页面的完整界面）与配套的 `README.md`：
数据概览、模型比较、最终评价、客户风险演示四页均可运行、可交互，全部数值来自真实数据与
组员交付的模型文件。这一棒让我学到的是：把「只在训练集拟合、用验证集选阈值、测试集只评一次」
这类**口径要求落到界面上**并不只是画图写卡片，而是要在代码结构上把「可交互探索」和
「锁定的最终结果」分开，否则测试集指标会在反复调参中被污染。
