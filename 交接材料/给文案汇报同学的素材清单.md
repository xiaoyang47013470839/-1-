# 界面设计这一棒 · 交接素材清单（v2 · 完善提高阶段）

> 用途：给负责「文案汇报」的同学写 PPT、总结报告和答辩讲稿用。
> 对应题目：计算机金融学导论 · 课程项目一 · 信用卡客户下月违约风险分析系统

## 一、这一棒做了什么（一句话）

用 Streamlit 实现**六个可切换页面**的完整可用界面：读取 A 岗清洗并构造衍生特征的 30,000 条数据、
B 岗调参后的模型产物，页面上的每个数值都由程序实际计算或加载，**没有静态设计稿、没有手填指标**；
并针对初版「违约类召回偏低」的缺陷补齐了 **D-1 模型对比、D-2 特征归因、D-3 调参过程、D-4 批量预测导出**。

## 三、答辩演示路径（建议按这个顺序点）

1. 启动：`streamlit run app.py` → 浏览器打开 `http://localhost:8501`
2. **数据概览**：统计卡片（30,000 条 / 违约率 22.12% / 缺失值 0）→ 三集划分表 → 分布图；强调「-2 = 无消费、-1 = 全额还款是编码，不是缺失值」
3. **模型比较**：讲「三个模型都只在训练集拟合」→ 看 ROC 三线叠加 → 点选不同模型 → **拖动阈值滑块**看精确率/召回率/报警人数实时变化
4. **调参过程**：说明初版召回只有 0.40、漏判严重 → RandomizedSearchCV 10 组 × 3 折 → 最优参数 → 召回 0.4040 → 0.6442（+24.02pt）
5. **最终评价**：锁定模型与阈值、测试集只评一次 → 混淆矩阵 2,662 / 843 / 343 / 653 → 讲漏判与误判的代价权衡
6. **客户风险演示**：输入 6 → 概率 40.02% < 阈值 45.79% → 低风险 → 再指归因条形图，说明「最新一期额度使用率、还款状态」如何推高风险
7. **批量预测**：默认预览验证集 4,500 条、报警 1,684 人（37.42%）→ 点导出 CSV 展示可交付结果

## 五、口径三句话（写进报告和 PPT 的核心）

1. **只在训练集拟合**预处理和模型（标准化放在 Pipeline 内，只对训练集 fit）。
2. **只用验证集**选模型和报警阈值（规则：召回率 ≥ 70% 的候选中精确率最高）。
3. **测试集只评价一次**，阈值固定后不再回头调整。

## 六、必须体现的合规表述

- 性别、年龄、教育、婚姻属于**敏感属性**，仅用于课堂公平性讨论；
- 统计**相关性不等于因果关系**，不能解释为「这些属性导致违约」；
- 结果**仅作教学示例，不作为授信决策依据**；
- 漏判（FN）可能增加损失，误判（FP）可能影响正常客户 —— 阈值就是这两者的权衡。
