# 信用卡客户下月违约风险分析系统（v2 · 完善提高阶段）

计算机金融学导论 · 课程项目一 · 组内「系统界面开发与可视化」分工交付。

本界面读取 A 岗清洗并构造衍生特征后的数据、B 岗调参后的随机森林模型，
覆盖题目要求的核心页面，并针对「违约类召回偏低」这一初版缺陷补上了
**调参过程展示、特征归因、批量预测导出**三项完善提高功能。

## 运行环境

- Python 3.10 及以上（开发时使用 Python 3.14）
- 依赖：`streamlit`、`pandas`、`numpy`、`scikit-learn`、`plotly`、`joblib`

```bash
pip install streamlit pandas numpy scikit-learn plotly joblib
```

## 启动步骤

```bash
# 1.（可选）重新训练模型与调参：生成 models_v2 下的全部产物，约 40 秒
python train_models_v2.py

# 2. 启动界面
streamlit run app.py
```

启动后浏览器自动打开 `http://localhost:8501`。
`models_v2/` 已随包提供，正常情况下跳过第 1 步即可直接运行。

## 数据与模型口径

- 数据：`03_credit_default_features.csv`，30,000 条；训练 / 验证 / 测试 = 20,999 / 4,500 / 4,501。
- 特征：基础 23 列 ＋ 衍生 6 列（`utilization_09`、`avg_utilization_6m`、
  `repayment_ratio_6m`、`trend_pay_status`、`overdue_count_6m`、`bill_std_6m`）。
- 预处理与模型只在训练集拟合；阈值只用验证集选择（规则：召回率 ≥ 70% 的候选中精确率最高）；
  测试集只评价一次。
- 随机森林调参采用 `RandomizedSearchCV`（n_iter=10，cv=3，scoring=roc_auc），
  最优参数与 B 岗交付一致（`max_depth=8`、`class_weight=balanced` 等），
  本机复现验证集 AUC 0.8017，与 B 岗报告的 0.8013 差异 0.0004（scikit-learn 版本差异）。
- 敏感属性（性别、年龄、教育、婚姻）仅用于公平性讨论；界面全程提示
  「相关性不等于因果，结果仅作教学示例，不用于真实授信决策」。

## 关键结果（可直接写入 PPT）

| 指标 | 初版 baseline | 调参后随机森林 | 梯度提升树 | 逻辑回归 |
| --- | --- | --- | --- | --- |
| 验证集 AUC | 0.7811 | **0.8017** | 0.8011 | 0.7726 |
| 验证集违约召回@0.5 | 0.4040 | **0.6442** | 0.3859 | 0.3146 |
| 验证集 F1@0.5 | 0.4981 | **0.5675** | 0.4945 | 0.4264 |
| 测试集 AUC | 0.7587（初版） | **0.7857** | 0.7866 | 0.7578 |
| 测试集召回（阈值选定后） | 0.6697（初版） | **0.6556** | 0.6566 | 0.6777 |

- 调参把违约召回从 40.40% 拉到 64.42%（+24.02 个百分点），代价是精确率从 64.94% 降到 50.71%。
- 测试集混淆矩阵（阈值 0.4579）：TN 2,662 / FP 843 / FN 343 / TP 653。
- 新增 6 个衍生特征使 AUC 从 0.7506 提升到 0.7576（+0.0070，A 岗同条件对照实验）。

## 界面分工说明（供个人报告引用）

- 负责文件：`app.py`（六个页面）、`train_models_v2.py`（调参与产物生成）、`README.md`、系统截图。

  D-4 批量预测与导出（含加载态、友好报错）。
- 关键测试：
  1. 调参参数与 B 岗一致时，本机验证集 AUC 0.8017 vs B 岗 0.8013，差异 < 0.001；
  2. 六页在 744px 窄视口下逐页实测，统计卡片数值无省略号截断（`scrollWidth > clientWidth` 检查为空）；
  3. 演示页输入非法编号给出有效范围提示；缺少模型文件时提示运行 `train_models_v2.py` 而非白屏；
  4. 批量预测 4,500 条耗时 < 2 秒，导出 CSV 编码为 utf-8-sig（Excel 直接打开不乱码）；
  5. 上传缺少特征列的 CSV 时给出缺失列提示，不崩溃。

## 关键 AI 交互（供 AI 交互日志与个人报告引用）

开发采用「自然语言描述需求 → 生成代码 → 本人运行测试 → 反馈问题 → 再修改」的循环：

1. **需求描述（生成初版）**：向 AI 说明数据文件、模型文件与口径要求，AI 返回四页版 `app.py`。
2. **界面结构重构**：本人实测发现单文件 `st.sidebar.radio` 切换后上一页最后两个卡片残留，
   向 AI 描述后改用 `st.navigation` + `st.Page`，残留消失。
3. **代码缺陷修正**：AI 初版写成 `y_tr.to_numpy() and y_va.to_numpy()`，本人核对后改为 `y_va.to_numpy()`。
4. **多模型页重构**：要求新增「进阶树模型 + ROC 叠加 + 一键切换」，AI 给出三模型结构；
   本人发现本机 Python 3.14 无法安装 xgboost（无 cp314 轮子），改用 sklearn 的
   `HistGradientBoostingClassifier` 作为梯度提升树，保证部署环境零额外依赖。
5. **特征归因实现**：`shap` 包同样无 Python 3.14 轮子，与 AI 讨论后改为自实现
   置换采样 SHAP（模型无关、可解释性等价），并加入「基准概率 → 本客户概率」的对照说明。
6. **批量页交互缺陷**：浏览器实测发现窄视口下侧边栏覆盖主区，按钮点击无效；
   同时首次进入无结果、演示效果差。改为首次进入自动生成验证集预览，并保留按钮重算其他范围。
